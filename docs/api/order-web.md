# React 订单页面

已接入商品详情购买入口、确认下单、买入/卖出分页列表、订单详情及取消/双方确认。沿用现有 React 单页状态切换与原生 dialog，未引入路由库或改变商品管理数据来源。

## 页面行为

- 仅在售且非本人商品展示购买入口；匿名用户先登录，服务端仍独立校验商品状态和参与者。
- 确认下单展示商品、卖家及价格，说明无线支付、线下交易和双方确认规则；勾选了解后才能提交。当前金额供核对，订单金额快照以服务端为准。
- 创建请求只发送字符串 product_id 与 Idempotency-Key 头。接受 202 返回的 PENDING，跳转买入订单详情，不伪装预占或成交成功。
- “我的订单”含“我买到的 / 我卖出的”，分别请求 role=buyer/seller，支持分页、总数、空状态与错误重试。订单契约没有商品标题快照，列表明确显示商品编号，不伪造名称或跨权限读取已售商品详情。
- 详情显示真实状态、金额、参与者、期限、创建/关闭时间和双方确认；已完成不代表收到在线支付。仅未到期 RESERVED 的参与者可以取消或首次确认。已记录一方确认仍可取消；客户端时间仅控制提示，服务端时间才决定是否接受操作。
- 取消和成交确认前二次确认，发送空请求体；不乐观写成终态，按实际响应展示 CANCELLING / CONFIRMING 等状态。

## 安全重试与资源释放

下单前将随机结算键保存到 sessionStorage，按买家及商品隔离。网络失败、超时、关闭后重新进入或刷新时复用原键；仅在取得真实订单响应后清理。未能使用会话存储时禁止发出创建请求，避免刷新丢失未知请求的键。网络结果未知时可重试或进入“我的订单”核实，不自动换键或自动重发写入。

订单列表存在处理中记录时每五秒刷新；详情处理中及 RESERVED 时每 2.5 秒刷新，终态停止。查询失败停止自动刷新，保留手动入口。离开页面、切换买卖角色或账号、关闭详情会取消当前读取并清理定时器；写操作期间禁止关闭对话框，卸载时仍取消请求，未知下单键继续保留。退出清理受保护页面状态，401 使用既有登录失效逻辑。未实现浏览器后台暂停轮询。

ID、金额、版本均保持字符串，金额用 BigInt 展示。API 请求不记录 Token/密码，沿用 12 秒 fetch 超时、取消信号及错误 Request ID。内部服务凭据不进入前端。

## 验证与待验收

本轮 `npm --prefix frontend run build`、`npm --prefix frontend run lint`（无警告）、`npm --prefix frontend run test:orders` 和 `git diff --check` 通过。四个 Node 测试覆盖结算键稳定/隔离、创建请求大整数/幂等头和 202、取消确认空体/列表参数、超时错误及禁止自动重试。测试使用模拟 fetch，未冒充浏览器交互或后端联调；当前测试运行环境 Node 26.4.0，依赖 Node 原生 TypeScript 类型擦除及模块钩子。

尝试浏览器验证时，CUA 报浏览器访问宿主不可用，Python 环境也未安装 Playwright。因此未完成桌面/手机截图、点击及真实 User→Product→Order→Gateway 联调。代码包含移动端布局与焦点样式，但视觉效果尚未实际验收。未修改数据库或后端，未发布网站。

后续手动验收：两账号购买→预占→买卖列表→单方/双方确认→完成；主动取消和自动过期；重复点击、网络超时后同键重试、刷新页面、退出切换账号、大整数金额、窄屏和键盘操作。浏览器测试不能替代此前真实数据库并发测试。
